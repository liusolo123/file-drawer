# 04: 悬停唤出与自动收起状态机

Parent: `.scratch/file-drawer-v1/spec.md`

**What to build:** 鼠标移到屏幕顶部中央满 250 毫秒，抽屉展开，且原应用的键盘输入继续正常工作；鼠标离开面板 500 毫秒后收起，期间移回则取消。拖放、预览、右键菜单进行中不自动收起，结束后恢复收起规则。本票先只处理主屏；每屏热区留给 10。

**Blocked by:** 01 应用骨架与菜单栏唤出空面板

**Status:** ready-for-agent

- [ ] 悬停热区不足 250 毫秒即离开时不展开
- [ ] 停留满 250 毫秒后在触发屏幕展开，且不在其他应用里打字时不抢焦点
- [ ] 鼠标离开面板 500 毫秒后收起；期间移回则取消收起
- [ ] 进入「交互保持」（拖放、预览、菜单）期间不自动收起，最后一个交互结束后恢复收起规则
- [ ] 状态机不持有真实定时器，时间由外部注入
- [ ] 单测用注入时间覆盖全部状态转移，不使用真实等待
- [ ] 隐藏时若焦点在面板内，交还展开前的前台应用

## Comments

### 2026-11-10 实现完成，等待人工验收

核心库新增 `PanelStateMachine`（纯状态机，注入时间）：

- 状态：隐藏、悬停待定、可见、待收起、交互保持。
- 事件：悬停进出、指针进出面板、时间推进、交互开始/结束、焦点进入、dismiss。
- 动作：显示（可声明是否抢焦点）、收起（声明是否交还焦点）、聚焦搜索框（05 使用）。
- 250/500 毫秒为构造参数，后续可调；不持有任何定时器。

应用层新增：

- `HoverMonitor`：50ms 轮询鼠标位置，主屏顶部中央 260×6 热区；不用全局事件监听，也不创建覆盖窗口，因此不请求辅助功能权限、不拦截点击。
- 悬停展开走 `showWithoutFocus()`：只 `orderFrontRegardless`，不激活应用、不抢键盘焦点。
- 热区视为面板的一部分，悬停菜单栏期间不会误收起；离开后面板 500ms 收起。
- 焦点交还：点击外部收起时焦点留在被点击的应用；Esc 收起时交还展开前的前台应用。
- `beginInteraction()` / `endInteraction()` 已暴露，等 08/09 接入预览、菜单与拖放。

自动验证：`swift test` 36/36（新增 11 条状态机用例），覆盖 250ms 门限、重复悬停不重置、500ms 收起、移回取消、交互保持与嵌套、交互结束按指针位置分支、dismiss 的焦点交还、隐藏态忽略事件。

待人工确认：悬停展开不抢焦点、移开自动收起、移回取消、Esc 交还焦点。

### 2026-11-10 悬停时灵时不灵的修复

用户反馈唤出成功率不稳定。定位到两个原因：

1. 热区只有屏幕顶部 6px 高，而菜单栏本身有 25–37px；用户通常停在菜单栏视觉中间，落在热区之外。
2. 热区按 `NSScreen.main` 计算，它是「有键盘焦点的屏幕」，不一定是鼠标所在屏幕。

修复：

- 热区改为**鼠标所在屏幕**的整条菜单栏高度、中央 320px 宽；菜单栏自动隐藏时保留 12px 最小高度。
- 几何计算移入核心库 `HoverGeometry`，新增 4 条测试（菜单栏覆盖、最小高度、窄屏收窄、副屏居中）。
- 测试与构建改用各自独立的 scratch 目录，并加 `scripts/test.sh` 处理 SwiftPM 宏插件缓存异常。
